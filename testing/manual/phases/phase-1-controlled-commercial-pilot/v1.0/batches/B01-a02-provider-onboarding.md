2. Run cases in table order unless a case says otherwise.
3. In each case row, fill only these columns:
   - **Actual result / data**: what you observed and the exact values you entered, for example "Saved; status shows Draft; total 2,450 GBP".
   - **Result**: `Not tested`, `Pass`, `Fail`, or `Blocked` (give the reason in Notes). `Retired` is set by the plan owner only.
   - **Notes**: usability observations (what you did, what happened, why it was confusing or slow), even when the case passes, plus any questions.
   - **Evidence**: links to your screenshots or recordings, separated by `, `. Upload each file to the evidence folder the team shares with you, named `<case base ID>-<YYYYMMDD>-<n>.<ext>` (run date, then a counter), for example `PR02-FR004-03-20261019-1.png`, so a retest never overwrites earlier files. Record only the links; do not send files with the batch.
   - **Bug status**: set `Found` when you see a bug; otherwise leave `—`.
   - **Last tested**: the date you ran the case, `YYYY-MM-DD`.

## Flow Overview

This batch tests how a Hairline admin brings a new clinic onto the platform and controls its account status. It is the first step of the Phase 1 pilot journey: no provider can receive inquiries or send quotes until it has been onboarded here.

- **Onboarding (FR-015 › Main Flow: Admin Creates and Activates New Provider).** The admin opens Provider Management, clicks "Add New Provider" and completes the six-step creation wizard: basic info, professional details, clinic info, documents, commission and review. The provider is created as Active, but it has no password yet, so it is held out of inquiry distribution. The owner gets an activation email with a one-time link valid for 24 hours, sets a strong password, logs in and sees the "Welcome to Hairline" prompt (FR-032).
- **Activation recovery (FR-015 › Alternative Flow A1).** If the email is lost or expired, the provider can request a new one from the login page, or the admin can resend it from the provider profile. Older links stop working.
- **Profile administration (FR-015 › Screen 3).** The admin edits basic information (every save needs a reason; Seat Limit changes need the admin password), manages languages and documents, and invites staff on the provider's behalf from the Staff List tab (FR-009 Screen 12).
- **Status control (FR-015 › Alternative Flows A5–A6, Screens 4–5).** The admin can suspend a provider, which leaves it able to log in but in read-only mode with a banner. The admin can reactivate it, or permanently deactivate it, which blocks login. Every action is recorded in the Activity Log.
- **Scheduled status changes (FR-015 › Business Rules, Scheduled Status Change and Cancel Scheduled Change).** A future Effective Date schedules the change: the provider keeps its status, Provider Management and the profile header show a "Scheduled" marker, and a daily job at midnight UTC applies it on the date. The admin can cancel a pending change with a reason and re-authentication, and reactivating a provider cancels any pending change.
- **Admin permissions (FR-031).** Admins without the onboarding and status permissions must not be able to perform these actions.

Phase 1 also tests scheduled (future-dated) suspension and deactivation and "Cancel Scheduled Change" on {V4} (A02-FR015-21 to A02-FR015-23). The booking and treatment parts of the suspension cascade, commission editing, Featured management, closure requests and "Login as Provider" are out of scope (see plan §1.2).

## Shared Preconditions

- The Phase 1 build is deployed to the admin dashboard (`https://admin.hairline.app`) and the provider dashboard (https://admin.hairline.app, the same origin as the admin dashboard; sign in with a provider account), and its version is recorded in the plan.
- {A1} (Super Admin) can sign in to the admin dashboard.
- {A2} can sign in to the admin dashboard. Its admin role is Support Staff with the FR-031 default permissions: View Providers ticked; Edit Providers, Onboard Providers and Suspend Providers not ticked. The team creates this account before testing (plan.md section 3).
- {V1}, {V2} and {V4} are Active providers whose owners have set their passwords.
- {V1}'s team has at least 2 members (the owner and {S1}).
- Setup item DOC-V1: {V1} has at least one document that the provider uploaded itself; on the admin Tab 6 (Documents) it shows Uploaded By "Provider".
- {V4} has no open quotes and no Accepted, Confirmed, In Progress or Aftercare cases, and its Featured flag is off. {V4} is reserved for the suspend, reactivate and scheduled-change cases and is not used by later batches except B03 PR06-FR032-16. B01 leaves {V4} Active; the team suspends it before B06 (plan.md section 3).
- GBP is an enabled currency in the FR-029 currency settings (the team confirms before testing).
- The team controls the fresh mailboxes {New provider mailbox 1}, {New provider mailbox 2}, {New provider mailbox 3} and {Invite mailbox 1}. None has been used on Hairline. {New provider mailbox 2} accepts plus-addressing (for example adding "+clinic02" before the @ sign). The addresses and mailbox access are shared privately and are not written here.
- Test upload files listed in the data sets are supplied with this batch by the team.
- Two browsers (or one normal and one private window) are available for two-session cases.
- Admin navigation: Provider Management is in the admin dashboard main menu. A provider's Provider Profile Details screen (tabs 1 to 8) opens by clicking the provider's row in Provider Management. When a Status filter is needed to find a provider, set it in Provider Management.
- Wizard rule used in several cases: "click next" means the wizard button that moves to the next step. The PRD does not name it; record its label once in Notes of A02-FR015-02.
- Timing: B01 runs over two days. A02-FR015-11 must start at least 25 hours after A02-FR015-10 ends. Run step 1 of A02-FR015-22 on Day 1 and its later steps on Day 2 after 08:00 Asia/Saigon time (the scheduled-change job runs at 00:00 UTC), followed by A02-FR015-23. Other cases can continue meanwhile.
- If a case needs the team to act, ask the plan owner (contact in plan.md section 3).
