## How to Fill In This File

1. Before starting, fill **Tester** and **Build tested** in Batch Control.
2. Run cases in table order unless a case says otherwise.
3. In each case row, fill only these columns:
   - **Actual result / data**: what you observed and the exact values you entered, for example "Saved; status shows Draft; total 2,450 GBP".
   - **Result**: `Not tested`, `Pass`, `Fail`, or `Blocked` (give the reason in Notes). `Retired` is set by the plan owner only.
   - **Notes**: usability observations (what you did, what happened, why it was confusing or slow), even when the case passes, plus any questions.
   - **Evidence**: screenshot or recording file names, named `<case ID>-<n>`, for example `PR02-FR004-03-1.png`. Send the files with the batch.
   - **Bug status**: set `Found` when you see a bug; otherwise leave `—`.
   - **Last tested**: the date you ran the case, `YYYY-MM-DD`.
4. The team fills **Bug ID** and moves Bug status to `Logged`, `Fixed - retest`, `Closed`, or `Reopened`. When you retest a `Fixed - retest` case, update only the result columns.
5. Do not edit IDs (keep the ` r1` suffix), titles, preconditions, test data, steps, or expected results, and do not use the vertical-bar character inside cells. Put questions or proposed changes in **Notes**.

## Flow Overview

Once patients are paying and travelling for treatment, Hairline staff must be able to take a support request, work it, answer the person, and close it with a clear record. FR-034 gives the admin team one Support Center for every request, whether the admin logs it from an email or phone call (Main Flow: Patient Support Case Lifecycle) or it arrives automatically from the provider portal or the patient app (Alternative Flows A3, A4, A5).

This batch tests the basic admin handling of a case: finding cases (Screen 1: Support Case Listing), creating one with field validation (Screen 2 and Alternative Flow B1), reading the case and replying in its communication thread, adding internal notes (Screen 3), the fixed lifecycle Open → In Progress → Resolved → Closed (Rule 2), resolving (Screen 4), reassigning (Screen 5), reopening (Screen 6 and Flow B3), escalation (Flow A1), attachment limits (Flow B4), deep links to patient and provider records (Flows A2 and A6), the audit timeline, and access limits for internal notes (Privacy Rule 4).

The batch also covers admin oversight of patient-provider messaging (FR-012 Admin Platform Screens 5, 6A and 6B). The admin finds conversations in the Communication Monitoring Center, reads a thread without being able to post in it, flags a conversation for observation without telling the patient or the clinic, resolves a flag, and sends an emergency intervention message that both sides see with the "Hairline Admin" badge. These cases use the conversations that B07 created.

Actors: Super Admin `{A1}` (holds Support Staff), second Support Staff admin `{A7}`, restricted admin `{A4}` (Support Center access without the "View Internal Notes" permission), and restricted admin `{A6}` (no Support Center access). Patient and provider submissions used here are prepared by the team as setup data. When a step needs a patient or provider action or an inbox check, ask the plan owner (contact in plan.md section 3) and give the case ID and step. Provider-side Help Centre screens, the Support Center Configuration screen, and case analytics are later phases and are not tested here.

Screen paths used in this batch (admin dashboard URL in plan.md section 3):

- Support Case Listing (Screen 1): main admin navigation > "Support Center".
- Create case (Screen 2): Support Center > "Create New Case".
- Case detail (Screen 3): Support Center > click a case row (or its "View" action).
- Resolve, Reassign, Reopen modals (Screens 4 to 6): buttons on the case detail screen.
- Communication Monitoring Center (FR-012 Screen 5): main admin navigation; FR-012 does not name the menu label, so record the path you used in Notes. Thread detail (Screens 6A and 6B): click a conversation in the list.
