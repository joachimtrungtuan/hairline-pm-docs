## Flow Overview

Providers answer patient questions about a quote and coordinate the booked treatment through in-app messaging. A conversation opens automatically when a provider sends the first quote to a patient, and the same conversation is reused for every later quote to that patient (FR-012 › Entry Points, Automatic Chat Creation; Main Flow step 1). The provider reaches conversations from the Messages popup in the header (Screen 3: Messages List) and works in the three-panel chat view (Screen 4: Provider ↔ Patient Chat): conversation list, message thread with compose area, and patient information with quote references.

This batch tests the provider side end to end over the real message transport: quote-based eligibility, sending and receiving text, real-time and offline delivery with durable notifications, read receipts, attachments and their limits (Alternative Flows A1 and B1), connection loss (B2), patient identity masking before payment, provider isolation, and the display of an admin emergency message. It also includes one audio and video call case, because the Phase 2 exit gate requires calls to be either proven or formally excluded.

Patient-side and admin-side actions (sending, reading, answering a call, the admin emergency message) are performed by the team on request; this batch only observes and judges the provider dashboard. To request one, ask the plan owner (contact in plan.md section 3) and give the case ID and step. Admin monitoring and intervention screens (FR-012 Screens 5 to 6B) are not tested here; B08 tests them (A10-FR012 cases), using the conversations this batch creates.

Screen paths used in this batch (provider dashboard URL in plan.md section 3):

- Messages List (Screen 3): the Messages icon in the provider dashboard header opens it as a popup over the current page.
- Provider ↔ Patient Chat (Screen 4): click a conversation in the Messages popup.
- Inquiry list and quote form: Inquiries screen (reach via the main menu; record the path you used in Notes).

Timing tolerances (FR-012 › SC-017, SC-019, User Story 2): a sent message appears in the thread within 2 seconds; a new-message notification and the header badge update within 5 seconds; a read receipt appears within 2 seconds of the patient opening the conversation. Measure with a stopwatch or the device clock from the moment the action is confirmed.
